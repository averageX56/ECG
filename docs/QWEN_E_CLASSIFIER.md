# Классификатор после обученного Qwen E

Запускается независимо от обучения разметчиков. Используется принятый `best_checkpoint`
из `qwen_4b_E_curriculum/selection.json`, а не обязательно последний cycle.
Файлы Qwen, U-Net и исходные pseudo caches не изменяются.

В notebook `04_all_pipelines_a100.ipynb` выполните новую секцию «Qwen E: final
classifier and U-Net comparison» после настройки окружения. Предыдущие обучающие ячейки не нужны.
Или из корня проекта:

```bash
python -m pipelines.gpu.interval_classification --config configs/qwen_E_classifier.json
```

Пути задаются в JSON; стандартный запуск рассчитан на уже обученный E/4B из скриншота.
Если catalog устарел, сначала `python -m pipelines.cpu.run audit`.

Архитектура: шесть многомасштабных residual Inception-блоков (ядра 9/19/39),
ветка RR/PR/QRS/QT/T и признаков формы с масками отсутствующих значений,
attention и max pooling по сокращениям, multilabel sigmoid по диагнозам записи.
Это собственная адаптация идеи [InceptionTime](https://arxiv.org/abs/1909.04939),
а не воспроизведение оригинального ансамбля и не заранее доказанный победитель на ЭКГ.
Диагноз записи не копируется в качестве истинного класса каждого сокращения.

Три одинаковых по протоколу варианта: `waveform`, `unet`, `qwen`. У двух fusion-моделей
одинаковая архитектура, seed, crop/R detector, train/valid/test, бюджет и criterion.
Интервалы вычисляются на полной длине записи. Классификатор получает до 64 равномерно
выбранных сокращений по всей записи; `max_beats` можно увеличить до запуска.
Используется II, иначе MLII, иначе первый доступный канал. Это одноканальный
эксперимент; остальные отведения не поступают в классификатор.

Все читаемые записи catalog обрабатываются без лимита количества записей. Источники
с поддержанным SNOMED mapping используют существующую политику разбиения. Прочие
источники получают только предсказания, без переноса beat labels в record diagnoses.
MIT-BIH CSV из `data_root/mit-bih` добавляются отдельно с проверкой калибровки по
`artifacts/mit_headers`; они получают предсказания диагнозов без метрик record diagnosis,
поскольку их истинные метки описывают отдельные сокращения.
Неизвестные диагнозы не считаются отрицательными. Классы допускаются только при наличии
положительных записей в каждом поддержанном датасете и >=20 positive и negative TRAIN
records. Проверка выполняется после удаления дубликатов и записей без сокращений;
исчезнувший источник не исключается из требования автоматически.
Неподдержанные классы и причины исключения перечисляются в `diagnosis_coverage.json`.
Нулевое количество обнаруженных crops исключает запись из классификации и отражается
в coverage. Ошибка чтения/вычисления останавливает подготовку, а не молча меняет когорту.
Точные дубликаты оставляют в наиболее защищённом split; пересечения известных
пациентов между split вызывают ошибку.

`artifacts/cluster/qwen_E_classifier/` содержит:

- `comparison.csv/json`: метрики трёх веток на valid, test, external, по каждому
  источнику, на объединённом holdout и на всех имеющих диагнозы записях.
- `common_diagnoses_v1/*/best.pt`: обученный классификатор, train-only normalization, thresholds,
  имена классов и хеши разметчиков; `latest.pt` для продолжения прерванного обучения.
- `common_diagnoses_v1/*/predictions.npz`: вероятности всех пригодных записей, включая неизвестные диагнозы.
- `diagnosis_coverage.json`: коды классов, positive/negative/unknown по источникам,
  train support, выбранные классы и причины исключения остальных.
- `inputs/coverage.json`, `manifest.csv`, `duplicates.csv`: охват и идентичности;
  `inputs/{qwen,unet}/*.npz`: crops, интервальные признаки, peaks, полный список волн.
- `inputs/interval_agreement.json`: разница интервальных признаков и количество
  доступных измерений обоих разметчиков по каждому источнику на всём корпусе.
- `manual_comparison.json`: Dice на известных samples LUDB/QT validation,
  границы/ширины на LUDB test и QT external (частичная ручная q1c, precision неизвестна).

Epoch и финальный вариант выбираются только по validation AUROC; thresholds — по
validation F1. `all_labeled_descriptive` включает classifier train и поэтому является
описательной метрикой всего корпуса. Для оценки классификатора отдельно опубликован
`heldout_all_sources`. По сообщению пользователя Qwen E обучался с данными всех
датасетов: это фиксируется в `evaluation_status`; holdout классификатора нельзя
объявлять доказанно новым для разметчика. На датасетах без ручных интервалов нет
метрики истинного качества P/QRS/T; диагнозы там оцениваются независимо, если известны.

Готовые shards проверяются по хешам и повторно используются. Готовые ветки пропускаются,
прерванное обучение продолжается с optimizer/scheduler. При смене данных, параметров
или чекпоинтов нужен новый `output`. Для повторного использования модели на новой
записи доступен `ClassificationPredictor` из training/interval_classification.py.

## Общие диагнозы и разные коды

По локальному catalog до фильтрации сигналов общими для CPSC, CPSC_EXTRA, PTBXL,
CHAPMAN, GEORGIA и STP являются **AF, PVC, SVEB, AVB, IVCD, RBBB, STD, STE**.
RBBB, депрессия ST (STD) и подъём ST (STE) — новые классы. ST-изменения являются
ЭКГ-признаками, а не самостоятельным подтверждением ишемии или инфаркта.
AVB1/2/3 и VT по отдельности условию присутствия во всех источниках не удовлетворяют.
При другом составе catalog список рассчитывается заново.

Словарь находится в `ecg_project/data/classifier_labels.py`. Источники кодов:
[официальная scored-таблица PhysioNet](https://github.com/physionetchallenges/evaluation-2021/blob/main/dx_mapping_scored.csv),
[unscored-таблица](https://github.com/physionetchallenges/evaluation-2021/blob/main/dx_mapping_unscored.csv).
RBBB объединяет `59118001` и `713427006`; неполная RBBB остаётся только в более
широкой группе IVCD. PVC включает `427172004`, `17338001`, парные экстрасистолы
`251182009` и пропущенный ранее `164884008` (ventricular ectopics).
STD включает `429622005` и inferior ST depression `704997005`; STE — `164931005`.
Группы AF/PVC/SVEB/AVB/IVCD объединяют диагноз и его подтипы; это не утверждение
о тождественности всех медицинских кодов. RBBB и IVCD могут одновременно быть положительными.

Метки пересчитываются из `labels` существующего catalog без повторного audit.
Старый словарь других пайплайнов не изменён. LUDB, QT и MIT не входят в пересечение:
текущие адаптеры не дают сопоставимых диагнозов всей записи.
Наличие кода во всех источниках не доказывает полноту отрицательной разметки.
Выбор общего словаря использует наличие меток и в holdout; веса, thresholds и
выбор модели по-прежнему не настраиваются по external/test.

После обновления перезапустите kernel и ячейку классификатора с прежним `output`.
Готовые `inputs/{unet,qwen}` совместимы и будут проверены и переиспользованы.
Новые головы обучаются в `common_diagnoses_v1/`; старые папки веток сохраняются.
Сводные `comparison.csv/json` после завершения относятся к новому запуску.
