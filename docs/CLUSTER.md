# Одна A100 40/80 ГБ через Jupyter

Основная инструкция: [FRESH_START.md](FRESH_START.md). [CPU/GPU и перенос](../pipelines/README.md), [QLoRA и Qwen](LORA.md).

Перед арендуемой GPU-сессией подготовьте данные локально с `--workers 4`. Переносите готовые кэши, сохраняя относительные пути. Qwen скачивает сам кластер при RUN_QWEN=True; остальные скачанные базы можно перенести.

Единственный notebook: `notebooks/04_all_pipelines_a100.ipynb`. Включайте нужные RUN-флаги; по умолчанию обучения нет. После очистки графики отсутствующих результатов пропускаются. Полное обучение A100 не ограничено локальным лимитом времени, но имеет epochs/early stopping. Не запускайте несколько GPU-ветвей одновременно.

BF16/TF32, gradient checkpointing и адаптеры применяются в больших ветвях; Beat-BERT подбирает batch. Batch HuBERT/Qwen — начальные профили, максимальная утилизация A100 локально не измерена. Контролируйте memory и examples/s; accumulation увеличивает effective batch, а не загрузку GPU сам по себе.

`python scripts/preflight.py --profile final|bert|lora|qlora|qwen` проверяет выбранные файлы и оборудование (укажите одно имя профиля). Отсутствующие обученные модели после очистки ожидаемы. Новые run-каталоги сохраняйте целиком. Валидация не должна открывать test для выбора моделей.
